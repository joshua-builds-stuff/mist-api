# Security policy

This is an unofficial assistant skill and example toolkit, not a production
webhook service. Use least-privilege tokens and test network changes on one
low-impact object first. Never include credentials or tenant payloads in issues.

For a suspected vulnerability, use the repository's **Security → Report a
vulnerability** private reporting option if enabled. If unavailable, contact the
repository owner through their GitHub profile and request a private reporting
channel before sharing details. Do not open a public exploit/credential report.

Include the affected revision, a minimal reproduction with synthetic data, and
expected impact. Only the latest main revision is actively maintained; update
before reporting. No response-time or production-support SLA is promised.
